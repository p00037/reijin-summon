# CPUの防衛・回復・陣地維持の実装計画

**目的:** [Issue #51](https://github.com/p00037/reijin-summon/issues/51) の4項目を全CPUデッキへ反映する。

**構成:** 既存のTypeScript製プランナーを拡張する。共通の防衛・安全位置判断を `cpuDefense.ts`、建築候補と面積評価を `cpuElementals.ts` にまとめ、各デッキの能力・陣形の判断は維持する。

**制約:** ゲーム共通の攻撃・復活・建築ルールは変更しない。資料は日本語。既存の `feature51` ブランチで作業する。

## 採用する判断

- 自陣側の半面と、召喚士・完成エレメントの凸包内にある敵エレメントを防衛対象とする。回復中を除き、近い前衛を優先して対象ごとに1体割り当てる。召喚士への直接の脅威は既存の迎撃を優先する。
- 敵召喚獣の近くでHP95%以下、または次の2撃が危険なら早めに撤退する。接触減速・移動速度・敵火力から離脱に必要なHPを見積もり、足りない場合は接触前から避ける。敵の進路を外れてから安全な回復経路を選ぶ。敵召喚獣が活動中は95%以上まで回復する。通常の撤退・復帰は35%・70%を維持する。
- 復活候補は召喚士と回復範囲内の複数地点。戦場内・復活可能・通常攻撃とレーザーの範囲外であることを確かめ、安全地がなければMPを温存する。位置で避けられない全体攻撃は位置選択の除外条件にしない。
- 建築は6基を目標に補充し、固定地点が埋まった場合は代替地点も使う。初期配置後は陣地面積の増分も評価する。味方召喚獣の活動中も、安全な担当者による補充を認める。

## 確認する境界条件

- 防衛対象のない敵陣のエレメント、破壊済みエレメント、回復中のユニット。
- 召喚獣戦での早期撤退、回復途中の再出撃、死に至る高威力攻撃。
- 近接攻撃・レーザー・全体攻撃、戦場端、安全な復活地点がない場合。
- 既存地点の占有、建築中と予約中を含めた6基上限、狭い陣地の拡張。
- 各デッキの能力、射撃停止、護衛、潜在能力による無料復活の維持。

## 検証結果

- `npm test`: 共有174件、クライアント427件、サーバー25件、合計626件成功。
- CPU関連86件を実行し、3デッキの6基確保・面積維持と、実際に時間を進めた撤退・回復を検証した。
- `npm run typecheck`、`npm run build`、`git diff --check` は成功。ビルドには既存のバンドルサイズ警告がある。
- 通信制限下では接続テストが失敗したため、ローカル通信を許可した実行で全テストを確認した。
- 別エージェントのレビューで、正面撤退による死亡と、レーザー経路補正後に通常攻撃範囲へ入る問題を発見した。離脱前の生存見積もり、側方・後方への離脱、安全な回復経路の検査を追加し、再現テストで修正を確認した。
- 仕様上の判断: すでに近接した低HPユニットは移動だけで救えない場合があるため、通常の接近段階で危険を予測して回避する。全体攻撃は場所で回避できないため、復活候補の全面除外には使わない。
