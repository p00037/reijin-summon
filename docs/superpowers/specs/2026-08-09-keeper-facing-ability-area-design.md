# キーパーの向き連動アビリティ範囲 設計書

## 目的

キーパーのアビリティ範囲を固定方向ではなく、画面上のカードが向いている方向へ配置する。黄色い範囲表示、対象マーク、使用可否判定、実際の対象選択を同じ向きで計算し、見た目と効果を一致させる。

## 対象範囲

- プレイヤー側キーパー（`PlayerMelee`）のアビリティ範囲だけを変更する。
- 円の大きさとキーパーからの距離は既存仕様を維持する。
- マスター、シーカー、CPU側の処理は変更しない。
- 停止中はカードが保持している最後の向きを使う。
- 復活直後は既存表示と同じ上向きを使う。

## 採用方式

`BattleScene` が描画用に保持しているカード回転角を、アビリティの範囲照会と `UseAbility` コマンドへ渡す。カードの向きを戦闘状態へ重複保存せず、現在の表示をそのまま判定の入力にする。

他の候補として、向きを `BattleState` へ追加する方式と、移動先から向きを推測する方式を検討した。前者は移動、復活、状態生成まで変更範囲が広く、後者は停止中の最後の向きを再現できないため採用しない。

## 範囲計算

カード回転角を `rotation`、カード縦サイズを `H`、キーパーの位置を `(x, y)` とする。現在の回転角0で使っている `+Y` 方向を基準として、範囲円の中心を次の式で求める。

```text
center.x = x + sin(rotation) * H
center.y = y + cos(rotation) * H
radius   = H / 2
```

これにより、回転角0では現在と同じ `+Y`、`π / 2` で `+X`、`π` で `-Y`、`-π / 2` で `-X` へ中心が移動する。カードの回転に合わせて円の中心だけが回転し、円の半径は変更しない。

## データフロー

1. `BattleScene` は `unitCardRotations` から選択中キーパーの回転角を取得する。未登録の場合は既存のプレイヤー初期角度0を使う。
2. 範囲表示と対象マークの生成時に、その回転角を `abilityArea` と `abilityTargets` へ渡す。
3. HUDの使用可否判定にも同じ回転角を渡す。
4. アビリティボタン押下時は `UseAbility` コマンドへ回転角を格納する。
5. `GameSession` はコマンドの回転角を `tryUseAbility` へ渡し、表示時と同じ範囲から対象を確定する。

回転角は有限数だけを受け付ける。不正な値を含むコマンドではアビリティを発動せず、APも消費しない。

## API変更

- キーパーの範囲を照会する `abilityArea`、`abilityTargets`、`canUseAbility`、`tryUseAbility` に回転角を渡せるようにする。
- `BattleCommand` の `UseAbility` に回転角を追加する。
- マスターとシーカーでは回転角を受け取っても既存結果を維持する。

## 表示

黄色い範囲円は回転後のワールド座標中心を既存どおり画面座標へ変換して描画する。対象エレメントのロックオンマークは、同じ回転角で抽出した対象だけに表示する。

## テスト

- 回転角0で既存の `+Y` 方向を維持する。
- 回転角 `π / 2` で `+X`、`π` で `-Y`、`-π / 2` で `-X` に範囲中心が追従する。
- `cardRotationForMovement` が画面右移動から生成する `π / 2` を表示範囲へ渡すと、world `+X` 側に範囲が表示される。
- 回転後の円内にある完成済み味方エレメントだけを対象にする。
- 範囲表示と実際の発動が同じ回転角を使う。
- 停止中の保持角度と、復活直後の初期角度0を使用する。
- 不正な回転角では発動せず、APを消費しない。
- マスターとシーカーの既存アビリティ結果を維持する。

## 完了条件

- キーパーの黄色い範囲円がカードの現在向いている方向へ表示される。
- 表示された円内の対象と、発動時に能力が付与されるエレメントが一致する。
- 停止しても最後の向きに範囲が維持される。
- 既存テスト、新規回帰テスト、型チェック、ビルドが成功する。
