# ユニット・召喚獣の静止カード画像化 設計仕様

## 目的

戦闘画面で使用しているユニットと召喚獣のアニメーション画像を、指定されたカード型の静止画像へ置き換える。ゲームルールや操作方法は変更せず、表示表現だけをカード型へ変更する。

## 対象画像

| 対象 | 公開ディレクトリ内の画像パス |
| --- | --- |
| 召喚獣 | `/assets/summons/summon01.png` |
| Speed | `/assets/units/blue/blue001.png` |
| Melee | `/assets/units/blue/blue002.png` |
| Ranged | `/assets/units/blue/blue003.png` |

Player と CPU は同じ画像を使用し、既存のチーム別 tint によって所属を区別する。

## 表示設計

- 各画像は `Phaser.Loader.LoaderPlugin.image` で通常画像として読み込む。
- ユニットおよび召喚獣のゲームオブジェクトには `Phaser.GameObjects.Image` を使用する。
- カード画像は切り抜きや正方形への変形を行わず、元画像の縦横比を維持する。
- 通常ユニットは表示高を 72px に統一する。画像比率から表示幅は約 52px となり、従来の 52px 四方のユニットと同程度の横方向占有量を維持する。
- 召喚獣は表示高を 144px にする。画像比率から表示幅は約 108px となり、従来の 108px 四方の召喚獣と同程度の横方向占有量を維持する。
- 選択状態、チーム tint、HP 表示など、静止画像に依存しない既存の視覚表現は維持する。

## モーションの廃止

次の表示処理を戦闘シーンから取り除く。

- ユニットおよび召喚獣のアニメーション定義作成
- 状態に応じた idle、walk、attack、damage、defeated アニメーション切り替え
- 移動方向に応じた左右反転
- アニメーション終了待ちに関する表示制御

移動、攻撃、被ダメージ、撃破・復活、召喚獣の生成・消滅はゲーム状態に従って従来どおり処理する。カード画像は状態にかかわらず静止表示とし、撃破中の表示・非表示など既存のライフサイクルは維持する。

## コード構成

主な変更対象は `src/client/src/game/scenes/BattleScene.ts` とする。

- テクスチャキーと画像パスを新しいカード画像へ更新する。
- スプライト用 Map を画像用 Map に変更する。
- 作成・同期処理を静止画像向けに簡素化する。
- 戦闘ロジックから独立したアニメーション判定モジュールは、他から参照されなくなった範囲を削除する。

ゲーム状態、戦闘ルール、ステータス設定、AI、HUD の仕様は変更しない。

## エラー時の扱い

画像読み込みに失敗した場合は Phaser の既存ローダーエラー処理に委ねる。代替画像や新しい通知 UI は追加しない。指定画像はリポジトリに存在することをビルド前に確認する。

## テストと検証

- 静止カード用のテクスチャ設定が、対象ごとに正しい画像パスを返すことを自動テストで固定する。
- アニメーションに依存しない既存の戦闘ルールテストがすべて成功することを確認する。
- TypeScript の型検査を含むクライアントビルドを実行し、`Sprite` から `Image` への変更に型エラーがないことを確認する。
- ローカル表示で、4種類のカード、チーム tint、縦横比、移動、攻撃、撃破・復活、召喚獣の生成・消滅を目視確認する。

## 対象外

- カード画像自体の加工・圧縮
- 赤チーム専用画像の追加
- カード枠、名前、ステータスなど新しい UI の追加
- ゲームバランス、当たり判定、選択範囲の変更
- 召喚者およびエレメント画像の変更
