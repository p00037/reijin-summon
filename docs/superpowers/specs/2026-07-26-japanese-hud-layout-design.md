# HUD日本語化・再配置設計

## 目的

戦闘画面のHUDを日本語化し、参考画面に近い情報階層へ整理する。召喚士HPと残り時間を上部へ、召喚ゲージを下部へ分離し、操作ボタンを戦闘フィールド外の右側へ縦配置する。

戦闘フィールドの幅と高さは現行値を維持する。上部HUDと重ならないように、フィールドの縦位置だけを下へ移動する。

## 画面構成

### 上部固定バー

画面上部に固定バーを配置し、次の3要素だけを表示する。

- 左: 自分の召喚士HPバー
- 中央: 実際の残り時間
- 右: 敵の召喚士HPバー

HPバーには日本語ラベルと数値を重ねる。

- 自分: `自分 1800 / 2000`
- 敵: `敵 1650 / 2000`

数値は `現在HP / 最大HP` とし、現在HPは整数へ切り上げて表示する。バーの比率は現在HPを最大HPで割った値を0〜1へ制限して使用する。

残り時間はモックアップの固定値ではなく、`BattleState.remainingSeconds` を毎フレーム反映する。整数へ切り上げ、`残り 300秒` から `残り 0秒` までカウントダウン表示する。

### 戦闘フィールド

戦闘フィールドは次の条件を維持する。

- 幅は現行値から変更しない。
- 高さは現行値から変更しない。
- 横方向は現行どおり中央揃えとする。
- 上部固定バーと重ならない位置まで、縦方向だけを下へ移動する。
- ワールド座標と画面座標の変換には、移動後のフィールド矩形を使用する。

HUDと戦闘描画で座標計算がずれないように、画面サイズから上部バー、戦闘フィールド、下部バー、ボタン列の矩形を返す純粋なレイアウト計算を共有する。

基準となる960×540表示では、次の値を使用する。

- 上部固定バー: `x = 0`、`y = 0`、`width = 960`、`height = 48`
- 戦闘フィールド: 現行計算と同じ `width = 515.2`、`height = 368`
- 戦闘フィールドの横位置: `x = (960 - 515.2) / 2 = 222.4`
- 戦闘フィールドの縦位置: `y = 56`
- 戦闘フィールドの下端: `y = 424`
- 下部固定バー: `x = 0`、`y = 492`、`width = 960`、`height = 48`

異なる画面サイズでは同じ余白関係を保って再計算するが、本変更では960×540を動作保証対象とする。

### 右側ボタン列

戦闘フィールドの外側右に、正方形ボタンを下揃えで縦配置する。

960×540表示では各ボタンを52×52px、ボタン間隔を8pxとする。ボタン列の左端は戦闘フィールド右端から12px空け、列の下端を戦闘フィールド下端へ揃える。フィールドの幅と高さをボタン配置のために縮小しない。

上から次の順番で配置する。

1. エレメント生成
2. 召喚
3. Retry

ボタンの表示内容は次のとおりとする。

| 操作 | 表示 |
| --- | --- |
| エレメント生成 | `/assets/buttons/element_button.png` |
| 召喚 | `/assets/buttons/summon_button.png` |
| Retry | `R` |

`/assets/buttons/skill_button.png` は本変更では使用しない。

エレメント生成と召喚は文字を表示せず、画像だけを表示する。Retryだけは例外として、正方形ボタンの中央へ `R` の1文字を表示する。

### 下部固定バー

画面下部の固定バーには、自分の召喚ゲージだけを表示する。

- 表示: `召喚ゲージ 63%`
- 数値: `BattleState.playerSummonGauge` を0〜1へ制限し、100倍した整数値
- ゲージ比率: 制限後の値をそのまま使用

操作説明、選択中ユニット、召喚士HP、敵情報、エレメント数、残り時間、勝敗情報は下部バーへ表示しない。

## 日本語化

戦闘HUDから現在の英語表示を取り除き、画面に残る文言を日本語へ統一する。

表示する文言は次のとおりとする。

- `自分`
- `敵`
- `残り N秒`
- `召喚ゲージ N%`
- `勝利`
- `敗北`
- `引き分け`

現在の操作説明、ステータスメッセージ、選択中ユニット表示は廃止する。移動、エレメント生成、召喚不可理由などの一時メッセージもHUDへ表示しない。

試合終了時だけ、戦闘フィールドまたは画面の中央に次の勝敗表示を重ねる。

- `PlayerWin`: `勝利`
- `CpuWin`: `敗北`
- `Draw`: `引き分け`
- `InProgress`: 表示なし

## ボタン状態と操作

### エレメント生成

次の条件をすべて満たす場合だけ有効とする。

- 試合結果が `InProgress`
- 自分の通常ユニットが選択されている
- 選択ユニットのモードが `Active`
- 選択ユニットが生存している

既存のエレメント配置可否判定とコマンド処理は変更しない。

### 召喚

試合中かつプレイヤーが召喚可能な場合だけ有効とする。召喚可能条件は既存のゲームルールを使用し、HUD独自の異なるルールを増やさない。

### Retry

Retryは現在どおり常に操作可能とし、押すと戦闘シーンを再開始する。

### 無効状態

無効な画像ボタンは半透明または暗い色調で表示し、クリック入力を受け付けない。有効状態へ戻った場合は通常の明るさとクリック入力を復元する。

## HUDの入力範囲

HUDの入力判定は次の領域だけを含む。

- 上部固定バー
- 下部固定バー
- 戦闘フィールド外の右側ボタン列

戦闘フィールド本体はHUD領域に含めない。これにより、既存のユニット選択とドラッグ移動を妨げない。

## アセット読み込み

`BattleScene.preload()` で次の画像をPhaserテクスチャとして読み込む。

- `/assets/buttons/element_button.png`
- `/assets/buttons/summon_button.png`

HUDは読み込み済みのテクスチャキーを受け取り、画像オブジェクトを表示・クリック対象として使用する。ボタン背景と枠は画像の背面へ置き、ホバーと無効状態の視認性を補助する。

## 状態更新

`BattleHud.update()` は毎フレームの `BattleState` と選択ユニットを受け取り、次を更新する。

- 自分と敵の召喚士HP数値
- 自分と敵のHPバー比率
- 実際の残り時間
- 自分の召喚ゲージ数値と比率
- 勝敗表示
- エレメント生成ボタンの有効状態
- 召喚ボタンの有効状態

召喚ボタンの有効状態には、ゲームルール側で判定した召喚可否を渡す。HUD内へ召喚条件の重複実装を持たせない。

## 破棄処理

HUDが生成した次のPhaserオブジェクトは、`destroy()` ですべて破棄する。

- 上部・下部の背景
- HPバーの背景・塗り・テキスト
- 残り時間
- 召喚ゲージの背景・塗り・テキスト
- 画像ボタン、Retryボタン、ボタン背景
- 勝敗表示

シーン再開後に古いHUDオブジェクトや入力イベントが残らないようにする。

## テスト

### レイアウト計算

- 960×540で戦闘フィールドの幅と高さが現在の計算結果と一致する。
- 戦闘フィールドの横位置が現行どおり中央である。
- 戦闘フィールドが上部固定バーより下へ配置される。
- ボタン列が戦闘フィールドの右外側にあり、重ならない。
- ボタン列が戦闘フィールドの下端に揃う。
- 下部固定バーが戦闘フィールドと重ならない。

### 表示値

- 自分と敵の召喚士HPが正しい日本語と数値になる。
- HP比率が0〜1へ制限される。
- `remainingSeconds` が毎フレームの `残り N秒` 表示へ変換される。
- `remainingSeconds` が負数でも表示は `残り 0秒` から下がらない。
- 召喚ゲージの数値と比率が0〜100%へ制限される。
- 勝敗が `勝利`、`敗北`、`引き分け` へ変換される。

### ボタン

- エレメント生成が `element_button.png` を使用する。
- 召喚が `summon_button.png` を使用する。
- Retryが `R` の1文字だけを表示する。
- `skill_button.png` を使用しない。
- 有効・無効状態に応じて入力可否と表示が切り替わる。

### 回帰確認

- 戦闘フィールド上でユニットをドラッグ移動できる。
- 上部・下部HUDとボタン上ではドラッグ移動を開始・確定しない。
- エレメント生成、召喚、Retryが従来どおり動作する。
- 960×540の実画面でHPバー、時間、召喚ゲージ、ボタン列が重ならない。

## 対象外

- 戦闘フィールドの幅・高さの変更
- ゲームルール、攻撃間隔、HP、召喚ゲージ速度の変更
- 新しいスキルボタンまたはスキル機能の追加
- ボタン画像そのものの加工・差し替え
- タイトル画面や戦闘画面以外のUI刷新
- レスポンシブ画面比率の全面的な再設計
