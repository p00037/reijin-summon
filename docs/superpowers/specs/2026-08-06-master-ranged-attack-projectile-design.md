# マスター遠距離攻撃の魔法弾演出設計

## 目的

マスター（内部種別 `Ranged`）の攻撃時に、攻撃元から攻撃対象へ白く発光する小さな魔法弾が飛ぶ演出を追加する。魔法弾は白い中心部と淡い黄緑色の光、進行方向へ伸びる短い尾で構成する。

本変更は表示演出に限定する。ダメージは従来どおり攻撃イベント発生時に即時適用し、魔法弾の着弾時刻とは同期させない。

## 表示仕様

- `AttackEvent.attackerUnitId` に対応する通常ユニットの `unitType` が `Ranged` の場合だけ、魔法弾を生成する。
- 魔法弾の画像には `src/client/public/assets/effects/melee_attack1.png` を使用する。
- 画像を小さく縮小し、加算合成を適用して、透明背景上の白い中心部と淡い黄緑色の発光を強調する。
- 画像の尾が攻撃元側を向くよう、攻撃元から攻撃対象への方向に合わせて回転する。
- 攻撃元の画面座標から攻撃対象の画面座標まで、約250ミリ秒で等速直線移動させる。
- 移動完了後は魔法弾のゲームオブジェクトを破棄する。
- 攻撃元と攻撃対象が同じ画面座標の場合も、対象位置に短時間表示してから破棄する。
- マスター以外の既存攻撃表示は変更しない。

`melee_attack_2.png` と `melee_attack_3.png` は球形発光や大きな着弾表現に向いた素材であり、今回の短い飛翔演出には使用しない。

## 構成

### 表示計算モジュール

`src/client/src/game/render/rangedAttackPresentation.ts` を追加し、次の表示情報を純粋関数で計算する。

- 攻撃元と攻撃対象から求める回転角
- 魔法弾の表示寸法
- 移動時間
- テクスチャキー、アセットパス、描画深度

Phaserに依存しない計算と定数を分離し、単体テストで表示契約を検証できるようにする。

### BattleScene

`BattleScene.preload` で魔法弾画像を読み込む。

既存の攻撃イベント描画処理では、イベントの攻撃者を戦闘状態から取得する。攻撃者がマスターの場合は、次の手順で魔法弾を生成する。

1. 攻撃元と攻撃対象をワールド座標から画面座標へ変換する。
2. 表示計算モジュールの値を使って画像の寸法、回転、深度、加算合成を設定する。
3. Phaser Tweenで対象位置まで等速移動させる。
4. Tween完了時に画像を破棄する。

マスター以外のイベントには既存の白線描画を維持する。

## データフロー

1. `tickCombat` が従来どおりダメージを即時適用し、`recentAttackEvents` に攻撃元・対象位置・攻撃者IDを記録する。
2. `BattleScene` が当該フレームの攻撃イベントを読み取る。
3. 攻撃者がマスターなら魔法弾画像とTweenを生成する。
4. 魔法弾は表示上だけ対象へ移動し、戦闘状態には影響を与えない。
5. 移動完了後、画像を破棄する。

攻撃イベントの型および戦闘ルールは変更しない。

## 例外・ライフサイクル

- 攻撃者IDに対応するユニットが見つからない場合は、魔法弾を生成せず既存処理を継続する。
- 画面座標上の移動距離が0でもTweenを生成し、短い発光として表示後に破棄する。
- シーン再起動・破棄時はPhaserがシーン配下のTweenとゲームオブジェクトを管理するため、独自の永続状態は保持しない。
- 同一フレームに複数のマスター攻撃が発生した場合は、イベントごとに独立した魔法弾を生成する。

## テスト

`src/client/src/game/render/rangedAttackPresentation.test.ts` を追加し、少なくとも次を検証する。

- 水平方向、垂直方向、斜め方向の攻撃で正しい回転角が得られること。
- 攻撃元と攻撃対象が同一点でも有限の回転角が得られること。
- テクスチャキー、アセットパス、表示寸法、移動時間、描画深度が意図した値であること。

実装後はクライアントの単体テスト、型チェック、ビルドを実行する。さらにローカル画面で、プレイヤー側とCPU側のマスター攻撃について、弾の向き、発光、移動、破棄、複数弾の同時表示を目視確認する。

## 対象外

- 着弾時へのダメージ適用タイミング変更
- 弾速に応じたゲームルール変更
- 着弾爆発、効果音、画面振動、パーティクルの追加
- マスター以外の攻撃演出変更
- `melee_attack_2.png` と `melee_attack_3.png` の利用または加工
