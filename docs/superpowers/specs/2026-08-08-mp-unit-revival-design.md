# MP消費型ユニット復活システム設計

## 目的

通常ユニットの10秒後自動復活を廃止し、召喚士ごとの共有MPを消費して撤退ユニットを任意のタイミングで復活させる。復活費用にはカードのCOST、MP自然回復速度には撤退中カードのLV合計を使用し、両者を独立した戦略要素として扱う。

同時に戦闘HUDを再配置し、撤退ユニットを戦闘フィールド下部の待機場所から自軍回復エリアへドラッグして復活できるようにする。ゲーム画面全体のサイズは既存の `644×468` を維持する。

## 対象範囲

- プレイヤーとCPUが個別に所有する共有MP
- MPの自然回復と召喚士被ダメージによる回復
- COSTを消費する通常ユニットの復活
- CPUの自動復活判断
- 撤退カードの待機場所と復活ドラッグ操作
- HP、MP、召喚ゲージ、残り時間のHUD再配置
- 関連するユニット状態、コマンド、テストの更新

召喚獣、エレメンタル、AP、デッキ編成画面、カード追加機能は対象外とする。

## 採用方式

MPと復活に関するルールは、新設する `resurrectionSystem` に集約する。`GameSession` は戦闘更新とコマンド受付の窓口として、このシステムを呼び出す。

既存の `unitSystem` は移動、戦闘、ユニット回復、撃破処理を担当する。`BattleScene` は待機カードの描画とドラッグ入力を担当するが、復活可否やMP消費を直接判断せず、`ReviveUnit` コマンドを `GameSession` へ渡す。

この分離により、復活ルールを描画から独立させ、プレイヤー操作とCPU操作で同一の検証処理を利用する。

## ユニットのLVとCOST

現在実装されている全通常ユニットは、チームと兵種を問わず次の値とする。

| 項目 | 値 |
| --- | ---: |
| LV | 3 |
| COST | 3 |

LVはMP自然回復速度の計算に使用し、COSTは復活時のMP消費に使用する。将来LVとCOSTが異なるカードを追加できるよう、同一の値としてまとめず別プロパティで保持する。

## MPの状態

プレイヤーとCPUは、それぞれ独立した共有MPを持つ。

| 項目 | 仕様 |
| --- | ---: |
| 戦闘開始時 | 0 |
| 最大値 | 10 |
| 所有単位 | 召喚士ごと |
| 用途 | 撤退した通常ユニットの復活 |

MP増加時は必ず10以下へ制限する。最大時に発生した自然回復や被ダメージ回復を持ち越すことはしない。

## MPの自然回復

MPは戦闘進行中だけ自然回復する。チームごとに撤退中の通常ユニットのLVを合計し、次の表からMP1回復に必要な時間を選ぶ。

| 撤退中LV合計 | MP1回復時間 |
| ---: | ---: |
| 0 | 25カウント |
| 1 | 24カウント |
| 2 | 21カウント |
| 3 | 19カウント |
| 4 | 16カウント |
| 5 | 13カウント |
| 6 | 9カウント |
| 7 | 5カウント |
| 8 | 4カウント |
| 9 | 3カウント |
| 10 | 3カウント |

1カウントは既存実装と同じく1秒として扱う。撤退中LV合計が10を超える場合は10の値を使う。

チームごとに小数のMP回復進捗を保持し、毎フレーム `deltaSeconds / T(L)` を加算する。進捗が1以上になった分だけ整数MPを加え、残りを次フレームへ持ち越す。撤退状況が変わった場合は、次のフレームから新しい速度を適用し、それまでの小数進捗は維持する。

MPが10に到達した時点で小数進捗を0へ戻し、上限超過分を破棄する。

## 召喚士被ダメージによるMP回復

召喚士が敵から受けた実ダメージをチームごとに累積し、最大HPの10%へ到達するたびにMPを1加える。現在の召喚士最大HPは8000のため、通常設定では累積800ダメージごとにMP1となる。

一度の攻撃で複数の10%境界を超えた場合は、その回数分のMPを加える。MPが10へ到達した場合は超過分を破棄する。将来召喚士最大HPが変更されても、固定値ではなく `maxHp × 0.1` から閾値を計算する。

## 撃破状態

通常ユニットのHPが0になった場合は、次を行う。

- `Defeated` 状態へ移す。
- HPを0にする。
- 生成中のエレメンタルをキャンセルする。
- 攻撃、回復、生成に関するタイマーをリセットする。
- 撤退順を記録する。
- 戦闘フィールド上のカード表示対象から外し、プレイヤーユニットは待機場所へ表示する。

既存の `unitRespawnSeconds`、`respawnTimerSeconds`、時間経過による自動復活処理は削除する。

## 復活コマンド

`BattleCommand` に `ReviveUnit` を追加する。コマンドはチーム、対象ユニットID、復活先座標を持つ。

復活は次の条件をすべて満たす場合だけ成功する。

- 試合とフェーズが戦闘進行中である。
- コマンドのチームと対象ユニットのチームが一致する。
- 対象ユニットが `Defeated` である。
- チームの現在MPが対象ユニットのCOST以上である。
- 復活先が戦闘フィールド内である。
- 復活先が同チーム召喚士の回復エリア内である。

成功時はCOSTと同じMPを消費し、ユニットを最大HPで `Active` に戻す。位置と移動先を指定された復活先へ設定し、攻撃、回復、生成の各タイマーと生成中状態を初期化する。

いずれかの条件を満たさない場合は状態を変更せず、MPも消費しない。

## CPUの復活

CPUもプレイヤーと同じMP回復および復活条件を使用する。CPUは復活可能な撤退ユニットが存在する場合、撤退順が最も古いユニットを優先し、CPU召喚士の位置を復活先とする。

CPUの判断周期は既存の1秒周期を利用する。復活判断を既存の召喚、エレメンタル生成、移動判断より先に評価し、復活したユニットは次回以降の判断から通常行動へ参加する。

## 戦闘中の処理順序

戦闘進行中の各更新では、概ね次の順序で処理する。

1. その時点の撤退LV合計からMP自然回復速度を計算する。
2. MP自然回復進捗を加算し、整数MPへ変換する。
3. エレメンタル、召喚ゲージ、移動、ユニット回復、戦闘、召喚獣を更新する。
4. 召喚士が受けた実ダメージをMP回復用累積値へ反映する。
5. 新たにHP0となった通常ユニットを撤退状態へ確定する。
6. CPU判断周期で復活可能なら、最古の撤退ユニットへ `ReviveUnit` を発行する。
7. 破壊済みオブジェクトと勝敗を更新する。

同一フレームに発生した撃破によるLV増加は、次のフレームの自然回復速度から反映する。

## 画面レイアウト

ゲーム画面全体は既存の `644×468` を維持する。上部HUDを撤去して戦闘フィールドを上へ詰め、左側に細い縦ゲージ、右側にボタンと残り時間、下側に待機場所を配置する。

左側HUDは横2列とし、それぞれを上下に分割する。

| 列 | 上 | 下 |
| --- | --- | --- |
| 左列 | 敵召喚士HP | 味方召喚士HP |
| 右列 | 味方MP | 味方召喚ゲージ |

各ゲージは縦方向へ増減する。バーの太さは現在の横ゲージの高さ28pxより細くし、基準値を約12pxとする。数値ラベルは小型画面でも現在値を識別できる最小限の表示とする。

残り時間は右側ボタン列の上へ配置する。既存のエレメンタル生成、召喚、Retryボタンは縦並びを維持する。

## 撤退ユニットの待機場所

戦闘フィールドの下に、プレイヤー側の撤退ユニットを並べる待機場所を設ける。生存中ユニットは待機場所へ表示しない。

待機場所の高さは画面全体を拡張せず、`644×468` 内の利用可能領域から確保する。カード画像は元の縦横比を保ち、待機場所の内側へ収まる最大サイズまで縮小する。複数カードがある場合は、横幅と間隔も考慮して全カードが収まる共通縮尺を使う。

撤退カードには `LV3 / COST3` と復活可否を表示する。MPがCOST未満の場合は暗く表示するが、カード自体は非表示にしない。

## ドラッグ操作

生存中ユニットの移動ドラッグと撤退カードの復活ドラッグを、ドラッグ開始位置とユニット状態で区別する。

- 戦闘フィールド上の生存カードから開始した場合は、既存の移動操作とする。
- 待機場所の撤退カードから開始した場合は、復活操作とする。
- 復活ドラッグ中は対象カードをポインターへ追従させ、復活可能な回復エリアを視認できる状態にする。
- 自軍回復エリア内でドロップした場合は `ReviveUnit` を発行する。
- 回復エリア外、MP不足、戦闘終了後、対象がすでに復活済みの場合はコマンドを成立させず、カードを待機場所表示へ戻す。

HUD、ボタン、待機場所以外へ対する既存の入力境界判定も、新レイアウトに合わせて更新する。

## 表示モデル

HUDモデルへ味方MPの文字列と比率を追加する。MP比率は `currentMp / 10` とし、表示値は整数とする。

待機カードの表示可否、縮尺、配置座標、暗転状態は、Phaser描画へ直接埋め込まず純粋なレイアウト関数または表示モデルとして計算する。これにより、画面サイズ固定、利用可能高さへの収容、複数カード時の共通縮尺を自動テストできるようにする。

## エラー処理と境界条件

- 負の経過時間はMP回復へ加算しない。
- MPは常に0以上10以下へ制限する。
- 撤退LV合計は回復時間表の0～10へ制限する。
- ダメージは実際に減少したHP量だけを累積する。
- 無効な復活コマンドは例外ではなく無操作として扱う。
- ドラッグ中に試合終了または状態変更が起きた場合は、ドラッグ状態を解除する。
- 同じユニットに対する重複復活では、最初に成立したコマンドだけがMPを消費する。

## テスト方針

### ルールテスト

- MP初期値が0、最大値が10である。
- 撤退LV合計0～10の各値で、指定時間ごとにMP1が回復する。
- 自然回復速度の途中変更で小数進捗を維持する。
- 最大MP到達時に超過回復と小数進捗を破棄する。
- 全通常ユニットが `LV3 / COST3` である。
- 召喚士が最大HPの10%相当の実ダメージを受けるごとにMP1が回復する。
- 一度に複数境界を超えるダメージを正しく処理する。
- MP不足、回復エリア外、生存中、別チーム、戦闘外の復活を拒否する。
- 復活成功時にMP3を消費し、最大HPと各タイマーを初期化する。
- CPUが最古の撤退ユニットを優先して復活する。

### UI・入力テスト

- `644×468` の画面サイズを維持する。
- 左HUDが2列・上下構成となり、残り時間がボタン上部にある。
- 戦闘フィールドが上へ詰められ、待機場所が下部へ収まる。
- 待機カードが利用可能な縦幅と横幅に合わせて等比縮小される。
- MP不足カードが暗転する。
- 復活ドラッグが回復エリア内だけでコマンドを生成する。
- 生存ユニットの移動ドラッグへ回帰がない。

### 回帰テスト

既存の戦闘、ユニット回復、エレメンタル生成、召喚ゲージ、召喚獣、CPU移動、初期配置、HUDボタンのテストを実行し、復活方式とレイアウト以外の挙動が維持されることを確認する。

## 完了条件

- 通常ユニットが時間経過だけでは復活しない。
- プレイヤーが待機カードを自軍回復エリアへドラッグし、MP3を消費して復活できる。
- CPUが同じルールで撤退順に自動復活する。
- 自然回復と召喚士被ダメージ回復が最大10の範囲で機能する。
- COSTとLVが別プロパティとして、それぞれ復活費用と自然回復速度へ使用される。
- `644×468` の画面内に、承認済みHUD、戦闘フィールド、右ボタン列、縮小可能な待機カードが収まる。
- 関連テスト、クライアント全テスト、型チェック、ビルドが成功する。
