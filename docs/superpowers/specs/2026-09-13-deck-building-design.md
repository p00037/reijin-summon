# デッキ編成機能 設計案

## 目的と状態

固定3体のローカルCOM戦を、選んだ1〜5枚のカードで遊べるようにする。以下の「確定要件」はユーザー回答に基づく。2026年9月13日に承認済み方針の実装を行った。検証結果は対応する実装計画の実行記録に記載する。

## 確定要件

| 項目 | 内容 |
| --- | --- |
| 合計コスト | 10以下 |
| 枚数 | 1〜5枚 |
| 同兵種 | 複数採用可能 |
| 同一カード | デッキ内の重複不可 |
| その他の編成制限 | なし |
| 使用可能カード | SC001〜SC020。最初から全カードを使用可能 |
| コスト・レベル・復活MP | 同じ値 |
| HP・攻撃力 | 指定Wiki一覧のカード別数値を採用 |
| 移動速度・射程・攻撃間隔・エレメント生成時間 | 現行の兵種別設定を共通で使用 |
| INT | データとして記録するが、戦闘には反映しない |
| アビリティ | 現行の兵種別アビリティを共通で使用。固有能力は後から追加 |
| カード画像 | カードごとに異なる新規イラストの生成を試み、難しい場合は既存画像を共用 |
| 編成画面 | カード一覧、能力詳細、追加・取り外し、編成中カード、合計コスト、出撃 |
| 保存 | 利用中のブラウザに複数デッキを保存。アプリ側の件数上限は設けない |
| CPU | 固定の標準デッキ |
| 初期配置 | 自動配置後に手動調整 |
| 戦闘終了後 | 同じデッキで再戦、編成に戻る、の両方 |
| 召喚獣 | 現行のまま。編成画面での選択は追加しない |
| 操作優先順位 | タブレット、タッチ対応PC、PCのマウス |

## カード情報の参照と扱い

参照元: [悠久の車輪@Wiki スケールギルド](https://w.atwiki.jp/ewwiki/pages/25.html)

対象は一覧中のsc001〜sc020の20件。名称、兵種、CO、LV、HP、AT、INTを読み取り、カード定義へ転記する。対象20件ではCOとLVは一致している。カード一覧は2009年1月11日更新と表示されており、今回はユーザー指定のこの一覧の値を採用する。

Wikiの固有アビリティ・パッシブスキル・召喚獣補正・関連キャラクター効果は今回の戦闘に追加しない。能力詳細には実際に使う兵種別能力を表示し、未実装の能力を使用可能と誤認させない。対エレメンタル攻撃倍率や停止回復など、既存の兵種特性は維持する。

画像は既存カード画像の転用ではなく、新規生成の方針とする。名前などの文字は画面側で重ね、イラストの生成結果に依存させない。

## 実装方針

### 1. カード定義と戦闘個体の分離

現在の`PlayerMelee`などは兵種と戦闘個体の識別を兼ねている。同兵種を複数採用するため、カード定義IDと戦闘個体IDを分離する。

- カード定義: カードID、名称、兵種、コスト、レベル、HP、攻撃力、INT、画像参照。
- 保存デッキ: デッキID、名前、順序付きカードID一覧。
- 戦闘個体: 戦闘個体ID、カードID、所属、位置、HP、AP、移動先など。

敵味方に同じカードがあっても戦闘個体IDは異なる。移動、攻撃、選択、マルチタッチ、移動先マーカー、撃破、復活、アビリティ対象は戦闘個体IDで管理する。元のカード定義を戦闘中に書き換えない。

### 2. 編成ルールの検証

共通の検証処理を用意し、編集操作と出撃時の両方で使用する。1〜5枚、コスト10以下、重複なし、全カードIDが有効であることを確認する。保存データも同じ基準で検査する。

編集中の空デッキは許容するが出撃不可とし、理由を表示する。追加できないカードにはコスト超過・枚数上限などの理由を表示する。

### 3. 編成画面

タイトルから編成画面へ進み、カードをタップすると詳細と追加操作を表示する。編成中カードはタップして取り外せる。スクロールと選択を区別し、マウスホバーやドラッグだけに依存しない。

カード一覧、選択カードの詳細、編成中カード、枚数、合計コスト、出撃操作を配置する。端末の表示幅に合わせて領域を組み替え、最大5枚の編成と主要操作を確認できるようにする。

複数保存に必要なデッキの新規作成、選択、名前変更、保存、削除を用意する案とする。絞り込み、検索、並べ替え、複製は初期版の必須範囲に含めない。

### 4. 保存

保存形式にバージョン、デッキ一覧、選択中デッキIDを持たせる。保存件数の独自上限は設けないが、ブラウザの容量上限や保存拒否は処理し、失敗した場合は保存完了と表示しない。

破損データや存在しないカードIDを検出しても起動不能にしない。該当デッキを出撃不可として修正できるようにする。ブラウザ間・端末間同期は今回の範囲外。

### 5. 戦闘への接続

出撃時に検証済みデッキのコピーを戦闘へ渡し、そのカードからユニットを生成する。編集や保存の変更が進行中の試合を変更しないようにする。

1〜5体を初期配置可能領域内に自動配置した後、既存の手動配置操作を使う。5体でも配置条件を満たせることを確認する。撃破カード欄、HP、AP、攻撃力、カード画像なども編成に応じて表示する。

再戦時は同じ双方の編成からHP・AP・MPなどを初期化する。編成に戻る場合は編集対象のデッキを保持する。

### 6. CPU標準デッキ

カード定義と検証はプレイヤーと共通にし、既存のCPU行動を利用する。CPUのアビリティ使用や戦術強化はこの機能の必須範囲に含めない。

標準デッキの具体的なカードは未指定。初期案はSC020（キーパー・3）、SC019（シーカー・3）、SC014（マスター・4）の3体、合計10とする。これはユーザー確定事項ではなく、実装時の標準編成案である。

## 作業順序

1. 20枚のカードデータを転記・照合し、デッキ検証処理を作る。
2. 戦闘個体IDを見直し、同兵種複数体と1〜5体の戦闘に対応する。
3. 自動初期配置、カード描画、撃破カード欄、入力、復活を可変編成へ対応させる。
4. 編成画面と複数デッキ保存を作る。
5. 出撃、CPU標準編成、再戦、編成へ戻る導線を接続する。
6. カード別画像を用意し、読みやすさを確認する。
7. 自動テスト、型チェック、ビルド、タッチ・マウス操作で検証する。

## 完成条件

- 指定の20枚を一覧から選択でき、カード別HP・攻撃力などが参照元と一致する。
- コスト10以下・1〜5枚・重複なしの条件を満たすデッキのみ出撃できる。
- 同兵種の複数カードや敵味方の同一カードが、HP・AP・移動・復活を独立して管理される。
- 1体、3体、5体の編成で初期配置、戦闘、勝敗、再戦が成立する。
- 異なるコストのカードが、それぞれのコストに応じたMPで復活する。
- 複数デッキを保存・選択でき、再読み込み後も復元できる。
- 保存失敗や破損データがあっても、原因を示して操作を継続できる。
- 固定CPUデッキと対戦でき、再戦と編成への復帰を選べる。
- タッチのスクロール・タップとマウス操作が使え、既存の戦闘マルチタッチが維持される。
- 既存機能の回帰を含むテスト、型チェック、ビルドと画面確認を実施する。
