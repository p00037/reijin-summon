# 生存ユニットカードのマルチタッチ移動設計

## 目的

複数の生存プレイヤーユニットカードを別々の指で同時に掴み、それぞれ独立した移動先へドラッグ操作できるようにする。ゲーム側では生存カード枚数に固定上限を設けず、将来ユニットカードが増えても入力状態のデータ構造を変更せず対応できるようにする。

## 対象範囲

- 生存しているプレイヤーユニットカードのドラッグ移動をマルチタッチ対応にする。
- Setup中の初期配置とInProgress中の移動命令の両方を対象とする。
- 各ポインターの押下、解放、画面外解放を独立して処理する。
- 復活待ちカードのドラッグ操作は既存の単一ドラッグ仕様を維持する。
- マウス操作による単一ドラッグは従来どおり利用可能とする。

## 制約

Phaser 3.90.0のInput Managerは最大10個のタッチポインターを扱える。ゲーム側のドラッグ状態はカード枚数に依存しない`Map`で保持するが、物理的に同時入力できる数はPhaserの最大10本と端末固有の同時タッチ上限のうち小さい方になる。

`Phaser.Game`の入力設定では`input.activePointers`を`10`に設定し、Phaserがサポートする最大数のタッチポインターを起動時に準備する。カード枚数そのものを3枚などの固定値で制限する処理は追加しない。

## アーキテクチャ

### ポインター単位のドラッグ状態

`BattleScene`が現在保持している単一の`draggedUnitId`を、Phaserの内部ポインターIDをキーとする次の状態へ置き換える。

```ts
Map<number, PlayerUnitId>
```

このMapは「どのポインターがどの生存ユニットを掴んでいるか」だけを表す。移動先マーカーは既存の`Map<PlayerUnitId, Vec2>`を引き続き利用する。

ドラッグ状態を操作する判定はPhaserに依存しない入力モジュールへ置き、次の責務を持たせる。

- ポインターへユニットを割り当てる。
- 同一ポインターの重複開始を拒否する。
- 別のポインターが既に掴んでいるユニットの重複割り当てを拒否する。
- 指定ポインターだけをドラッグ状態から解除する。
- 指定ポインターに対応するユニットを使って既存の移動確定判定を実行する。

状態遷移では呼び出し元から渡されたMapを直接変更せず、新しいMapを返す。これにより、複数ポインターが互いの状態を誤って解除しないことを単体テストで検証できるようにする。

### 入力イベント

`pointerdown`では次の順序で処理する。

1. 押下したポインターに残っている生存カードのドラッグ状態だけを解除する。
2. 復活待ちカードをヒットテストする。利用可能な復活カードなら既存の復活ドラッグを開始して終了する。
3. HUD上の押下なら終了する。
4. 生存プレイヤーユニットをヒットテストする。
5. ユニットが別のポインターに割り当て済みでなければ、押下ポインターへ割り当てる。

新しい`pointerdown`で別ポインターの生存カードドラッグは解除しない。復活カードの押下時にも、別ポインターの生存カードドラッグ状態は維持する。ただし復活カード自体は従来どおり同時に1枚だけ操作できる。

`pointerup`では、最初にそのポインターへ割り当てられた生存ユニットを取得する。生存カードの割り当てがある場合は、そのユニットだけを既存の`transitionDragRelease`へ渡し、移動または初期配置コマンドを確定してから当該ポインターだけを解除する。

生存カードの割り当てがなく、復活ドラッグ中である場合は既存の復活処理を実行する。これにより、生存カードを掴んでいる別の指を離しても復活ドラッグを誤って確定しない。

`pointerupoutside`ではイベントから受け取った`pointer.id`に対応する生存カードだけを解除する。ほかのポインターのドラッグと復活ドラッグは維持する。復活ドラッグを開始したポインターを識別できるようにし、そのポインターが画面外で解放された場合だけ復活ドラッグを解除する。

### 終了時の後始末

シーン生成時は空のMapで開始する。試合結果が確定した場合とシーンの再生成時には、生存カードの全ドラッグ状態と復活ドラッグ状態を解除する。

## コマンド処理

既存の`transitionDragRelease`、`GameSession.applyCommand`、`applyMoveCommand`はユニットIDごとに独立した移動先を処理できるため、ゲームルール層のコマンド形式は変更しない。

各指を離した時点で個別の`MoveUnit`または`PlaceInitialUnit`コマンドが発行される。イベントは順番に処理されるが、各ユニットの`destination`が独立して更新されるため、ゲーム上では複数ユニットが同じ時間帯に移動する。

## エラー処理と競合

- 同じカードを複数のポインターが掴もうとした場合、先に割り当てたポインターを優先する。
- 同じポインターから重複して押下イベントを受けた場合、古い割り当てを解除してから現在のヒットテストを行う。
- ドラッグ開始後に対象ユニットが倒された場合、既存の`targetUnitAlive`判定により移動コマンドを発行せず、そのポインターだけを解除する。
- HUD上、戦場外、Countdown中などの無効な解放では既存仕様どおりコマンドを発行せず、そのポインターだけを解除する。
- ある指の無効操作や画面外解放によって、ほかの指のドラッグ状態や移動先マーカーを消去しない。

## テスト方針

Phaserに依存しないドラッグ状態遷移の単体テストを追加し、最低限次を検証する。

- 異なるポインターへ異なる生存ユニットを割り当てられる。
- カード枚数を前提とした固定上限がなく、任意のポインターIDをMapへ追加できる。
- 同じユニットを2つのポインターへ割り当てられない。
- 一方のポインターを解放しても他方の割り当てが残る。
- 指を押した順序と異なる順序で解放しても、対応するユニットのコマンドが生成される。
- 無効な解放でも対象ポインターだけが解除される。
- 画面外解放でも対象ポインターだけが解除される。
- 既存の単一ドラッグ、Setup中の初期配置、移動先マーカー更新が維持される。

合わせてクライアントの型検査、全単体テスト、プロダクションビルドを実行する。

## 変更対象

- `src/client/src/main.ts`: Phaserの有効タッチポインター数を設定する。
- `src/client/src/game/input/dragMovement.ts`: ポインター単位のドラッグ状態遷移を追加する。
- `src/client/src/game/input/dragMovement.test.ts`: 複数ポインターの状態遷移テストを追加する。
- `src/client/src/game/scenes/BattleScene.ts`: 単一ドラッグ状態をポインター単位の状態へ置き換え、イベントを独立処理する。

## 完了条件

- 複数の生存カードを異なる指で同時に掴める。
- 各指を任意の順番で離しても、対応するカードだけに移動または初期配置命令が設定される。
- 同じカードを複数の指で同時に掴めない。
- 一方の指の無効操作や画面外解放が、他方の操作を中断しない。
- ゲーム側に生存カード枚数の固定上限がない。
- 復活カードの既存の単一ドラッグ動作を維持する。
- 既存テストを含むクライアントの全検証が成功する。
