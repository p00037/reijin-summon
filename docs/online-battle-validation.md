# オンライン対戦の検証記録

検証日: 2026-09-22。Windows、Node.js 22、ローカルのColyseusサーバーとPhaserクライアントで検証。

## 実装範囲

CPU戦を維持し、表示名・6桁ルーム番号で2人が参加するオンライン対戦を追加した。双方の準備後5秒で開始し、相手の編成・配置は開始まで非公開。試合はサーバーで進行し、切断から30秒以内の復帰、降参、双方の合意による再戦と再編成に対応する。全体の接続上限は10人。

カード固有スキルの追加とCPUの戦術強化は、この対人戦実装には含めない。

## 自動検証

npm test: 356件成功（shared 2、client 339、server 15）、失敗0。共有ルール・既存CPUルール・座標変換・部屋進行・接続制限・公開接続元・実通信を確認。npm run typecheck と npm run build も成功。既存のクライアント容量警告は残る。

## 負荷検証

専用ローカルサーバーに10クライアント・5ルームを接続。実行時間600秒、11人目拒否、操作送信、切断と復帰、5試合の決着と両者の結果一致、再戦要求を確認した。

| 測定 | 結果 |
| --- | --- |
| サーバー更新処理時間のp95 | 約1.56ms（基準50ms未満） |
| 終了時RSS | 105,095,168 bytes（約100.2MiB） |
| 送信データ量 | 52,670,094 bytes（約50.2MiB、WebSocketペイロード） |
| 決着数 | 5 |
| 切断からの復帰 | 成功 |

追加実行で実時間との比較を導入し、観測区間でのずれは最大約0.172秒だった。ただし追加実行のログは300秒台以降から終了まで空白があるため、連続10分の遅延検証としては扱わない。上表は30秒ごとの記録が継続した初回600秒実行の測定値。公開環境では連続した記録で再測定する。

ローカルPCでの測定であり、無料公開サーバーの性能・通信料金を保証する値ではない。送信量にはTLS・HTTPなどの通信上の追加分を含まない。固定ステップの余り時間は遅延蓄積の判定に使わず、実時間との比較を追加した。

再実行: ルートで npm run build:server、npm run test:online:load -- --spawn。短時間確認には --smoke を追加する。

## ブラウザーでの確認

- 2画面でルーム作成・番号での参加・デッキ選択・双方の準備を確認。
- 開始前の相手カード非表示と、開始後の表示を確認。
- 5秒カウントダウン中の準備取り消しと、再度の開始を確認。
- 対戦中のカード移動と、ページ再読み込み後の30秒以内の復帰を確認。
- 画面上部のルーム表示が戦場と重ならないように調整。縦画面には横向きの案内を表示。
- 両画面で時間切れの引き分けが一致し、双方の再戦希望後に同じルームの編成画面へ戻り、再び戦闘開始できることを確認。
- 降参の確認ダイアログ表示まで確認。その後のブラウザー操作がタイムアウトしたため、画面での退出完了は未確認。実通信の統合試験では明示退出による相手の勝利と降参理由を確認。
- CPU戦の出撃・敵の移動、攻撃、エレメンタル生成、HP減少を確認。
