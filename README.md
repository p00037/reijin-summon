# reijin-summon

TypeScript + Phaser client and Node.js + Colyseus server starter.

## Requirements

- Node.js 22 or newer
- npm

On Windows PowerShell, use `npm.cmd` if `npm` is blocked by the script execution policy.

## Setup

```powershell
npm.cmd install
```

## Development

Run the Colyseus server and Phaser client together:

```powershell
npm.cmd run dev
```

- Client: http://localhost:5173
- Server: http://localhost:2567
- Health check: http://localhost:2567/health

ローカルCOM戦MVPだけを確認する場合は、クライアント単体で起動できます。
サーバーは不要です。

```powershell
npm.cmd run dev:client
```

- Client: http://localhost:5173

## デッキ編成

タイトルの「CPU戦へ」から、カードを選んで詳細を確認し、「このカードを加える」で編成します。編成中のカードを押すと取り外せます。合計コスト10以下・1〜5枚で出撃でき、同じ兵種は複数採用できますが、同じカードは重複できません。

「新規」で複数のデッキを作り、名前を付けて保存できます。保存数にアプリ側の上限はありませんが、利用中のブラウザの保存容量に従います。保存は端末・ブラウザ・サイトごとで、編集内容は「デッキを保存」を押した時に保存されます。

編成画面の「対戦CPU」でデッキ1・デッキ2・デッキ3を選び、相手の召喚獣・戦い方・編成を確認して出撃できます。すべて合計コスト10です。CPUの選択は編成画面へ戻った場合と再戦で引き継ぎ、再戦のHP・AP・ゲージ・撤退判断は初期化します。オンライン対戦ではCPU選択欄を表示しません。

| 対戦CPU | 編成 | 召喚獣 |
| --- | --- | --- |
| デッキ1：機動・召喚型 | グー（SC012）・レッドアイ（SC009）・タイガーアイ（SC005）・ローズクォーツ（SC007） | リヴァイアサン |
| デッキ2：雨・陣地型 | ダライアス（SC015）・レッドアイ（SC009）・クリン（SC004）・ローズクォーツ（SC007） | ユグドラシル |
| デッキ3：射撃・陣形型 | アウイン（SC014）・チェルミ（SC013）・スペサルティン（SC003）・レッドムーン（SC010） | ランダム（対戦ごとに6種類から抽選） |

出撃後はカードをドラッグして初期配置を調整し、「配置を確定して戦闘開始」を押します。戦闘終了後は「同じデッキで再戦」と「編成に戻る」を選べます。

デッキ1はグーが中央、ローズクォーツが側面のエレメンタル生成を担当し、タイガーアイは初期3基の生成を補助した後、レッドアイと同じ敵を狙います。両CPUとも敵の接近時には建築を中断して迎撃し、HP35%以下、または傷ついた状態で複数の敵に孤立した場合は召喚士へ戻ります。撤退後はHP70%以上で復帰します。同じ移動指示を繰り返さず、回復時間を確保します。

デッキ1ではグーのゲージ回復、タイガーアイの方向指定の減速、ローズクォーツの移動・交戦時の自己強化を使います。レッドアイは相手が雨を降らせた場合に味方を加速します。リヴァイアサンは通常、戦場の10%以上の面積を確保して召喚します。召喚士への接近やHP35%以下の危機では即時召喚し、開幕90秒以降は面積条件による待機を解除します。

デッキ2ではクリンを後方に保ち、射程内では停止して射撃します。初期3基はクリン・ローズクォーツ・レッドアイで生成し、その後はローズクォーツが広い陣地を作ります。雨は初回AP3がたまってから使用し、残り10秒以下で更新します。同じ判断内で雨→レッドアイの加速→大津波を連携できます。ダライアスは複数の敵がいる半面へ位置取りし、2体以上への攻撃・1体の撃破・召喚士の防衛に大津波を使います。雨が切れた立て直しではクリンを優先して復活させます。

ユグドラシルは陣地面積によるHP、自然消耗、敵カード・召喚獣の火力から活動時間を見積もり、通常は約8秒以上を確保して召喚します。近接攻撃・レーザー・全体攻撃をそれぞれの範囲に応じて考慮します。召喚士HP30%以下での潜在能力や、召喚時の一撃で勝てる場合は早めに使用し、試合終了直前には活動時間の条件を緩和します。活動中は前衛を本体周辺に配置し、迎撃と陣地の維持を優先します。

デッキ3は後衛2体が中央の2基を生成し、前衛は1体ずつ外周を広げ、もう1体を護衛に残します。アウインは周辺人数によるゲージ回復、スペサルティンは移動加速をエレメンタルへ付与し、同じ効果を付与済みの陣地ではAPを温存します。チェルミは移動・撤退する味方へ向きを合わせて加速します。後衛は射程内で停止して射撃し、接近されたら後退します。前衛は陣形に近づいた敵を迎撃し、全員がHP35%以下で撤退、70%以上で復帰します。安全な立て直しではアウイン、防衛時には前衛を優先して復活させます。

デッキ3の召喚獣は対戦開始時に抽選し、試合中は固定、再戦時に再抽選します。ラファエル・バハムート・デュラハンの進軍には陣形で追従し、リヴァイアサン・ユグドラシル・ジャックポットでは陣地の維持を優先します。近接型は通常10%以上の陣地面積を確保し、危機や開幕120秒以降には待機を解除します。停止型は活動時間を見積もって召喚します。ジャックポットは味方をレーザー経路から退避させてから召喚し、活動中もレーザーを避けます。HP30%以下でラファエル・デュラハンを召喚できる時は、復活効果を使ってMPを残します。

カードは[参照一覧](https://w.atwiki.jp/ewwiki/pages/25.html)のSC001〜SC020を収録し、番号・名前・兵種・CO/LV・HP・AT・INTを登録しています。移動・射程・生成時間の基礎値は兵種共通で、固有アビリティと自動発動スキルに対応しています。INT差はダメージアビリティの威力と妨害の効果時間に影響します。

自動発動スキルは時間・HP・位置・雨・保持APによる強化、撃破時のAP回復、死亡時のゲージ・AP・HP・MP回復、その場での復活を実装しています。デッキ詳細と戦闘画面で説明を確認でき、条件の成立状態と回復・復活の成功も表示します。CPU戦とオンライン対戦で同じ処理を使い、抽選結果はオンラインではサーバーが確定します。数値と参照資料は[カードスキルの調査・確定仕様](docs/card-skills-research-and-proposal.md)を参照してください。

### 召喚獣の選択

デッキ編成画面でラファエル、ジャックポット、ユグドラシル、リヴァイアサン、バハムート、デュラハンの6種類から1体を選び、デッキと一緒に保存できます。旧形式の保存デッキにはラファエルを補完します。CPU戦の相手はデッキ1がリヴァイアサン、デッキ2がユグドラシルで、再戦でも同じ種類です。デッキ3は対戦ごとにランダムで、再戦時にも再抽選します。対戦中は種類を変更できません。

種類別のHP・移動速度・攻撃力・被ダメージ倍率と専用画像を実装しています。ジャックポットの味方を巻き込むレーザー、ユグドラシルの全体攻撃、リヴァイアサンの召喚時・周期波動にも対応しています。HPは基礎値＋カードのHP補正＋陣地面積1%につき60、自然消耗は毎秒120です。基礎HPが0の2種類も、カード補正で最終HPが正なら面積0で召喚できます。

各カードの召喚獣カスタマイズを編成全体で合算します。ATK上昇カードはレベル＋1、DEF上昇カードはコスト1につき被ダメージ率を4ポイント減算（ダライアスは10ポイント）、ザンダーは最大HP＋500です。被ダメージ率の下限は5%。6種類とも補正率は1倍で、死亡・復活・位置・国籍変更で補正は変わりません。召喚士攻撃・レーザー・波動にもATKの増加比率を反映し、潜在発動時の固定ダメージ・回復量は増やしません。カード詳細と編成画面に個別効果・合計・補正後の値を表示します。CPU戦・オンライン対戦で共通処理を使い、旧保存デッキも読み込み時に再計算します。資料と採用値は[召喚獣カスタマイズの仕様](docs/summon-customization-research-and-questions.md)を参照してください。

自軍召喚士のHPが30%以下で召喚すると、6体それぞれの潜在能力が自動発動します。回復・無料復活、AP・MP回復、全体ダメージ、時間制の強化・弱体、引き寄せに対応し、編成画面の説明と戦闘中の発動表示、オンライン同期を追加しています。Wikiの概算値と了承済みの仮設定は[潜在能力の仕様](docs/summon-potential.md)を参照してください。

数値・対象範囲・Wikiに記載のない部分の仮設定は[召喚獣選択仕様](docs/superpowers/specs/2026-09-17-summon-selection-design.md)、画像の生成記録は[画像README](src/client/public/assets/summons/README.md)に記載しています。

既存画像の対応番号は、旧blue001 → SC009（レッドアイ）、旧blue002 → SC012（グー）、旧blue003 → SC017（ローレライ）です。残る17枚は個別に生成したイラストを使い、画面と画像パスをSC番号に統一しています。

## Cloudflare Pagesへの公開

この手順ではゲーム画面を公開します。CPU戦はそのまま利用できます。オンライン対戦には、後述の対戦サーバーの公開と接続先の設定が別途必要です。

1. Cloudflareダッシュボードで **Workers & Pages** を開く。
2. **Create application** から **Pages** を選び、GitHubリポジトリを接続する。
3. ビルド設定に次の値を入力する。

| 項目 | 値 |
| --- | --- |
| Framework preset | `None` |
| Root directory | `/` |
| Build command | `npm run build:client` |
| Build output directory | `src/client/dist` |

環境変数 `NODE_VERSION` に `22` を設定してデプロイする。デプロイ完了後、発行された `*.pages.dev` のURLを開き、タイトル画面とゲーム内画像が表示されることを確認する。

以後はCloudflare Pagesで設定したproduction branchへpushすると、自動的に再ビルド・再公開される。

## オンライン対戦（公開前の検証中）

タイトルから「CPU戦へ」または「オンライン対戦」を選択します。CPU戦は従来どおり端末内で動作します。オンライン対戦は表示名を入力してルームを作成し、6桁の番号を相手に伝えて参加します。双方が編成・配置を決めて準備完了すると、5秒後に戦闘が始まります。相手の編成と配置は開始まで配信しません。

切断中も試合は進み、30秒以内は同じタブまたは「前の対戦に復帰」から戻れます。期限を過ぎると切断側が敗北します。双方が戻らない場合は中断です。サーバー再起動時の復旧・戦績保存はありません。

### ローカル・タブレットでの検証

1. Node.js 22を使用し、ルートで npm ci、npm run dev を実行します。
2. PCでは http://localhost:5173 を2つのタブで開きます。
3. タブレットはPCと同じWi-Fiに接続し、PCのLANアドレスの5173番を開きます（localhostはタブレット自身を指すので使いません）。PCのファイアウォールでプライベートネットワークの5173・2567番を許可してください。
4. 接続元を制限する場合は src/server/.env.example を src/server/.env にコピーし、ALLOWED_ORIGINS に実際のLANアドレスを含めます。
5. 検証結果・未確認事項は [検証記録](docs/online-battle-validation.md) を参照してください。

全自動試験は npm test、型検査は npm run typecheck、製品ビルドは npm run build です。10人・5試合・10分の負荷検証は npm run build:server 後に npm run test:online:load -- --spawn で専用のローカルサーバーを起動して実行できます。

### インターネット公開時に変更するもの

- ゲーム画面は既存のCloudflare Pages、対戦サーバーはRenderの単一インスタンスを候補とします。
- サーバー用の render.yaml を用意しています。無料プランを選び、ALLOWED_ORIGINS に実際のPagesのHTTPS URLを設定します（末尾の / は付けません）。未設定の本番起動は失敗します。
- Pagesのビルド環境で VITE_GAME_SERVER_URL を実際のRenderの wss:// URLへ変更し、クライアントを再ビルドします。HTTPS画面から ws:// には接続できません。
- サーバーはホストの PORT を使います。複数インスタンスへの拡張はこの構成の対象外です。更新は試合がない時間に手動で行います。
- 2026-09-22確認時点の [Render無料枠](https://render.com/docs/free) は、通信がない状態が15分続くと休止し、次の接続で起動します。起動待ち・予告なしの再起動による試合中断があり得ます。
- 無料インスタンスでも転送量の超過は別料金の対象です。[Render FAQ](https://render.com/docs/faq) によると支払方法未登録なら課金が必要になった時点でサービス停止となります。公開前にアカウントの支払方法・無料枠を確認し、費用が発生する変更は行いません。

現在は公開先を作成していません。実機と公開環境での検証が済むまで公開完了とは扱いません。
